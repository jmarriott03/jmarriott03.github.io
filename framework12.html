A clear hierarchy for consistent, accessible and flexible content

The framework provides the visual language and building blocks. The CMS uses this structure to assemble pages with consistent rules, while AI can use the same information to create and validate content.

1. Page and section structure

Defines the overall layout, content boundaries and full-width sections.

  • Page containers and maximum content width
  • Full-width and full-bleed sections
  • Page gutters and section spacing
  • Responsive behaviour at the page level

Paragraph text uses a shared readable measure targeting approximately 75 characters per line, separate from container width. Wider containers support layouts and collections without requiring wide paragraphs.

The framework determines gutters, widths and responsive behaviour rather than exposing arbitrary values to editors.

2. Groups and layout patterns

Groups associate related components and can share approved presentation. Layout patterns arrange components; the framework controls spacing, alignment rules, column widths and responsive stacking.

  • Shared background, padding and width
  • Consistent spacing between child components
  • Framework-defined borders and edge treatments
  • Behaves predictably when nested

Layout patterns

3. Components

Provide content, purpose and behaviour. Examples here illustrate the framework rather than defining the complete CMS component menu.

  • Clear purpose and content structure
  • Defined states (default, hover, focus, disabled…)
  • Accessible markup requirements
  • Permitted variations

Start with user needs, use the simplest suitable component and avoid separate components solely for different visual treatments.
