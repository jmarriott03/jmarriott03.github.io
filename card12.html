Accessible card patterns

A working HTML demonstration of six card/link arrangements, incorporating relevant WCAG 2.2 requirements and GOV.UK-style interaction guidance.

Card content Recommended approach Why
Title + description, one destination Linked title; optionally expand its pointer hit area Keeps a concise, meaningful link name and one keyboard focus target; the larger area is a pointer convenience.
Title + description + metadata, one destination Title link is safest Prevents descriptions, dates and status text from becoming an overly long link announcement.
Multiple links to different destinations Title link + separate links Each destination needs its own clear, keyboard-accessible link; a stretched link would conflict with them.
Buttons/actions as well as a destination Do not make the whole card a link Links navigate and buttons act; controls must remain separate and must not be nested.
Image + title leading to the same place One shared link, not two links Avoids duplicate Tab stops and repeated screen-reader link announcements for the same destination. Use alt="" if the image is redundant to the linked title.
Card is purely informational No link Avoids creating a misleading, unnecessary interactive target.

Implementation checks

  • Use a descriptive link in the card heading as the default pattern.
  • Do not put buttons, form controls or different links inside a stretched-link card.
  • Do not nest links or buttons inside one another.
  • Ensure every link has a clear purpose from its text and accessible context.
  • Consolidate image and title links when they have the same destination.
  • Use empty alternative text for images that are decorative or redundant.
  • Keep the default link styling distinguishable without relying on colour alone.
  • Provide a focus indicator that is visible, sufficiently contrasted and not clipped.
  • Check pointer targets against WCAG 2.5.8’s 24 by 24 CSS pixel minimum.
  • Check that enlarged card hit areas do not overlap adjacent cards or controls.
  • Test at 200% zoom, 400% zoom and narrow reflow widths.
  • Test links in a screen-reader links list, not only in their visual context.
  • Test with keyboard, touch, screen reader, zoom and forced-colour settings.
