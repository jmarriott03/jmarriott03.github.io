Accessible card patterns

A working HTML demonstration of six card/link arrangements, incorporating relevant WCAG 2.2 requirements and GOV.UK-style interaction guidance.

Card content Recommended approach Why
Title + description, one destination Linked title Keeps a concise, meaningful link name and one keyboard focus target. The description remains separate from the link.
Title + description + metadata, one destination Title link is safest Prevents descriptions, dates and status text from becoming an overly long link announcement.
Multiple links to different destinations Title link + separate links Each destination needs its own clear, keyboard-accessible link. Keeping links separate avoids overlapping or conflicting hit areas.
Buttons/actions as well as a destination Title link + separate buttons Links should handle navigation, while buttons should perform actions. Keep the link and buttons as separate controls and do not nest them.
Image + title leading to the same place One linked title; image kept separate Avoids duplicate Tab stops and repeated screen-reader link announcements. Use alt="" if the image is redundant to the linked title. The image is not part of the link's pointer target.
Card is purely informational No link Avoids creating a misleading, unnecessary interactive target.

Implementation checks

  • Use a descriptive link in the card heading as the default pattern.
  • Keep descriptions and metadata outside the heading link unless they are intentionally part of its link text.
  • Do not nest links or buttons inside one another.
  • Ensure every link has a clear purpose from its text and accessible context.
  • Keep images outside the link when the linked heading already communicates the same destination and purpose.
  • Use empty alternative text for images that are decorative or redundant.
  • Keep the default link styling distinguishable without relying on colour alone.
  • Provide a focus indicator that is visible, sufficiently contrasted and not clipped.
  • Ensure separate links and controls have distinct, usable pointer targets.
  • Test at 200% zoom, 400% zoom and narrow reflow widths.
  • Test links in a screen-reader links list, not only in their visual context.
  • Test with keyboard, touch, screen reader, zoom and forced-colour settings.
