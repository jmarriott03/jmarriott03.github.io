A responsive, utility-based CSS framework with a token-driven theming architecture.

A utility-based CSS framework with a token-driven theme system for managing colour, text and link styles across nested components. Defines reusable colour palettes and contextual surface tokens, allowing background, text and link colours to adapt to the active theme and surface. Includes responsive layout, spacing, typography, grid, image, button and border-radius utilities, with low-specificity styling designed to support predictable component nesting and reduce unintended global side effects.

1. Token-driven colour palettes

Each theme defines background, text and link colour values through CSS custom properties. Named palettes include mono, deep-rose, brilliant-rose, raspberry-red, deep-orange, butter-yellow, dark-lavender, bondi-blue, turquoise, sea-green, fresh-green, persian-indigo and midnight-blue, alongside dark.

2. Separation of palette and surface tokens

Palette variables such as --bg-color-light describe the theme's colours. Component-facing variables such as --color-text and --color-link resolve the appropriate values for a particular surface. This separation means the same .bg-color-light utility can work across different themes.

Â

3. Nested theme and surface behaviour

The data-theme attribute establishes a theme context, while .bg-color, .bg-color-light, .bg-color-medium and .bg-color-dark apply individual surfaces. This allows a component to use a different surface from its parent while retaining its own text and link colour rules.

Á

4. Responsive utility and layout system

The framework includes width constraints, responsive padding and margins, auto-fitting grids, flexible two-column layouts, image sizing, typography scaling and responsive border radii. It also includes a reduced-motion media query.

ê

5. Reusable component styling and legacy compatibility

Shared button variants, card utilities, border treatments and other helpers support consistent styling. Existing production classes are retained alongside newer utilities, allowing the framework to evolve without necessarily replacing established components.
